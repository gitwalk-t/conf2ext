# Skill: фиксация изменений в Git

## Когда использовать

Используй этот skill, когда пользователь просит зафиксировать, закоммитить, сохранить или отправить изменения в Git.

## Главное правило

Если пользователь говорит "фиксируй изменения в git" или похожую фразу без явного указания ветки, это означает фиксацию в ветку `main`.

Не выбирай случайную текущую ветку, codex-ветку, checkpoint-ветку или feature-ветку только потому, что она сейчас активна или использовалась раньше.

## Другая ветка

Другую ветку можно использовать только при явном указании пользователя, например:
- "зафиксируй в ветку codex/target-merge-revive"
- "сделай коммит в feature/..."
- "не трогай main, зафиксируй в текущей ветке"

## Перед фиксацией

1. Проверить текущую ветку.
2. Перед любыми commit/change operations сначала получить актуальные изменения из Git в локальный репозиторий.
3. Синхронизацию выполнять до анализа diff и до commit.
4. Если пользователь не указал ветку явно, целевая ветка всегда `main`.
5. Если изменения находятся в другой ветке, перенести их в `main` безопасно: merge, cherry-pick или точечный patch по ситуации.
6. Проверить итоговый diff уже в целевой ветке.
7. Не смешивать независимые задачи в один commit.

## Проверки

Перед фиксацией изменений в `main` по возможности выполнить:
- `go test ./...`
- `go build ./...`

Если изменение только документационное и проверки не запускались, явно указать это в ответе.

## Финальный ответ

В ответе указать:
- целевую ветку;
- commit SHA;
- краткое описание commit;
- какие проверки выполнены;
- если проверки не запускались — сказать об этом явно.

## Запреты

- Не фиксировать изменения в случайную текущую ветку без явного указания пользователя.
- Не считать codex/checkpoint/feature ветку источником истины без прямой команды.
- Не делать force-update основной ветки.
- Не удалять ветки без отдельной команды пользователя.
- Не смешивать cleanup веток и обычную фиксацию без отдельного запроса.
