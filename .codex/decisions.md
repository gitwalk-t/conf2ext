# Решения

- 2026-04-16 / Добавлены публичные обертки в `pkg/config` и `pkg/converter` / нужен простой стабильный entrypoint вне `internal` / внешний код должен использовать `pkg/*`
- 2026-04-16 / CLI по умолчанию берет `./configs/config.json` / в этой рабочей копии активный сценарий завязан на checked-in конфиг / root command можно запускать без `CONFIG_PATH`
- 2026-04-16 / Устаревшие алиасы (`included_objects`, `additional_adopted_objects`) оставлены как слой совместимости / схема конфига уже изменилась / объединение и нормализация не должны тихо ломать старые конфиги
- 2026-04-16 / Текущая бизнес-модель — `Native` или `AdoptedStub`, excluded-объекты не попадают в итог / XML-логика ушла от отдельного полноценного full adopted режима / если такой режим вернется, это нужно отдельно зафиксировать
- 2026-04-16 / `change.go` остается единым узким местом для классификации, очистки и замены GUID / активная отладка сосредоточена там / без прямого запроса не делать структурный рефакторинг
- 2026-04-16 / XML-термины `excluded`, `forbidden`, `RefDrivenInclusion`, `AdoptedStubExt(Form)` и `AdoptedStubExt(DefinedType)` зафиксированы как рабочий словарь / прошлые ошибки уже возникали из-за размывания терминов / будущие правки в `change.go` и документации должны использовать именно эти обозначения
- 2026-04-20 / Имя и префикс корня расширения централизуются через `extension` и `prefix` / из-за рассинхрона между `Configuration.xml` и `ConfigDumpInfo.xml` Конфигуратор может падать на проверке принадлежности основного объекта / оба файла и корневой `InternalInfo` должны обновляться согласованно
- 2026-04-20 / Корневой `Ext` не должен хранить `ParentConfigurations*`, если их нет в эталонной выгрузке / этот служебный артефакт ломал загрузку корня / при изменении корня надо синхронизировать и `Ext`
- 2026-04-20 / `Configuration.xml/ChildObjects` должен отражать весь итоговый top-level состав, включая `AdoptedStub` / очистка корня только по `native_prefixes` оставляет файлы и `ConfigDumpInfo.xml`, но скрывает объект из состава расширения / нормализация корня должна опираться на итоговые `decisions`
- 2026-04-20 / `AdoptedStubExt(Form)` определяется по полному field contract dynamic list, а не только по `MainTable` / прежняя логика слишком легко возвращала старые ошибки на `DataPath` и `RowPictureDataPath` / конвертер должен сам валидировать этот контракт до загрузки в 1С
- 2026-04-20 / При очистке adopted top-level metadata сохраняем пустой `ChildObjects`, если контейнер существовал в исходном формате / часть типов метаданных, например `ExchangePlan`, требует этот каркас даже при пустом составе / очистка не должна превращать документ в структурно невалидный XML для Конфигуратора
- 2026-04-20 / `Subsystem` в adopted-режиме должен сохранять верхний `ChildObjects` / подсистема иначе перестает читаться Конфигуратором / adopted-нормализация для `Subsystem` не должна срезать этот контейнер
- 2026-04-21 / Дочерние подсистемы нативной подсистемы тоже классифицируются как `Native`, и это не должно зависеть от списка special adopted-root / иначе `ConfigDumpInfo.xml` и дерево подсистем расходятся с реально сохраненными файлами ветки и Конфигуратор теряет вложенную подсистему / правило действует, пока ветка не исключена через `excluded_subsystems`
- 2026-04-20 / `AdoptedStubExt` для форм теперь удерживается по всем XML-ссылкам формы, а не только по `MainTable` / часть объектов с табличными частями терялась из-за слишком узкой эвристики / form-linked target objects должны сохраняться целиком, если форма на них опирается
- 2026-04-20 / `AdoptedStubExt(Form)` может возникать только через форму `Native`-объекта / формы non-native в составе не переносятся, значит они не могут быть источником этого режима / нужно держать границу между `Native` и `AdoptedStubExt` явной
- 2026-04-20 / `CommandGroup.Информация` должен сохраняться в составе как `AdoptedStub` / в старом рабочем дампе этот стандартный command group был нужен для команды объектов и его потеря ломала загрузку / корневая нормализация не должна выкидывать такие служебные группы
- 2026-04-20 / Для обычных `Native`-объектов не сериализуем явный `ObjectBelonging=Native` / Конфигуратор трактует native как дефолтный режим, а явная запись может искажать проверки типов предопределенных данных / `ObjectBelonging` явно пишется для adopted-режимов
- 2026-04-20 / Если регистр остается `Native`, его документы-registrators тоже дотягиваются в `Native` / иначе у документа пропадает `RegisterRecords` и регистр показывает ошибку о пустом наборе регистраторов / promotion должен идти и по обратной связи от регистра к документу
- 2026-04-21 / Для non-native top-level metadata формы убираются целиком, включая ссылки в `Properties` и дочерние записи в `ConfigDumpInfo.xml` / раньше форма уже удалялась как файл, но оставалась как ссылка или `Metadata`-запись и ломала загрузку расширения / adopted-объект не должен объявлять несуществующие формы ни в одном слое XML
- 2026-04-21 / Формы участвуют в `RefDrivenInclusion` и dynamic-list contract только для `Native`-владельцев / non-native формы в `ChangeFiles` еще могут временно существовать в `_tmp` до финального удаления, но не являются источником ссылок и не участвуют в form-driven валидации / `AdoptedStubExt(Form)` может возникать только из формы `Native`-объекта
- 2026-04-21 / Для owner-level поиска по `OwnerKey` приоритет всегда у top-level metadata XML / у одного владельца в дереве могут существовать `Ext/*`, формы и другие дочерние XML с тем же `OwnerKey`, и без приоритета валидатор начинает читать `Help.xml` или форму вместо основного объекта / проверки состава и реквизитов должны опираться на основной metadata XML
- 2026-04-21 / Валидация `dynamic list contract` смотрит на все field-bearing children top-level metadata XML, а не только на `Attribute` / часть регистров хранит реальные поля dynamic list как `Dimension` и `Resource`, и без этого конвертер получает ложную ошибку "поле не сохранено" / проверки должны учитывать `StandardAttributes`, `Attribute`, `Dimension`, `Resource`, `Measure`
- 2026-04-22 / Для `AdoptedStubExt` не заимствуем `Properties/StandardAttributes` / рабочий пример с `упо_ОграничениеДоступаПоОбъектамPM` показывает, что форма может ссылаться на `Ссылка` и `НомерКартинки`, а целевой каталог при этом остается минимальным adopted-объектом / стандартные поля нужно считать встроенными возможностями платформы, а не частью сериализуемого adopted-состава
- 2026-04-22 / Ошибку `Неизвестный объект метаданных - Configuration.<old>` в расширении нужно чинить очисткой `Role/Ext/Rights.xml` от прав на исходную конфигурацию, а не глобальным rename по всем XML / такие записи описывают права на базовую конфигурацию и не должны переживать `ChangeFiles`
- 2026-04-22 / `Role/Ext/Rights.xml` должен очищаться и от ссылок на дочерние metadata, которых уже нет в итоговом XML объекта / adopted-cleanup может убрать `Attribute`, `Command` или `TabularSection`, и права ролей не должны оставлять висячие ссылки на такой состав
- 2026-04-22 / При ошибках `Неизвестный объект метаданных` по дочерним путям сначала нужно проверять несогласованный хвост в правах и служебных XML со ссылками на metadata-path, а не только отсутствие самого объекта / практический минимум: `Role/Ext/Rights.xml`, `ConfigDumpInfo.xml`, корневые `Ext/*.xml` и другие XML-настройки, где ссылка живет в `name` / `Metadata` / `DataPath` / `Field` / `Command` / `object` / несколько расследований показали, что top-level объект уже бывает корректно очищен, а падает висячая ссылка в таком служебном слое
- 2026-04-22 / Ошибки `Неизвестная команда` для non-`Native` объектов нужно чинить чисткой `CommandInterface.xml` / `MainSectionCommandInterface.xml` и плоских child-записей `ConfigDumpInfo.xml`, а не возвратом самой команды в состав / adopted-cleanup уже может корректно убрать `Command`, но служебные XML обязаны синхронно убрать ссылки на нее
- 2026-04-21 / Этап `validate dynamic list contracts` зафиксирован как отдельная узкая проверка после записи XML и до `verify old GUID` / он проверяет только form-driven contract dynamic list, а не валидность всей XML-выгрузки / для standard attributes на этом этапе допускаются alias-имена, если форма ссылается на русские имена полей
- 2026-04-21 / Для упавшего на `validate dynamic list contracts` temp добавлен resume-режим `cmd/changefiles --resume-from-validation` / это позволяет продолжать отладку с текущего `v8_src*`, не повторяя полный `srcConvert`/`cfConvert` / resume-режим повторяет validation и cleanup, но не делает повторную проверку old GUID, потому что исходная карта замен уже потеряна
- 2026-04-21 / Field-level validation в `dynamic list contract` применяется только к non-Native target-объектам / у `Native` полная структура переносится целиком, и этот слой давал ложные срабатывания на form/query fields / валидатор по-прежнему проверяет существование объекта, но не требует у Native послойного совпадения полей с metadata XML
- 2026-04-21 / Для вложенных подсистем owner key строится по полной цепочке `Subsystem.<root>.Subsystem.<child>...`, а не только по последнему имени / иначе одноименные ветки подсистем смешиваются в одном `decision` и cleanup удаляет родительские XML при живых ссылках из `ConfigDumpInfo.xml` / top-level подсистема при этом сохраняет прежний ключ `Subsystem.<name>`
- 2026-04-21 / `Ext/CommandInterface.xml` должен быть командным зеркалом `Ext/MainSectionCommandInterface.xml` / загрузка расширения падала на подсистемных секциях в `CommandInterface.xml`, хотя рабочий пример хранит там командную структуру / нормализация должна убирать `SubsystemsVisibility` и `SubsystemsOrder` из `CommandInterface.xml` и приводить его к командному формату
- 2026-04-22 / Для `Subsystem` сохраняем контейнер `ChildObjects`, но чистим список вложенных `Subsystem` по итоговым `decision` / иначе top-level или native-подсистема остается в составе, а внутри нее висят ссылки на дочерние подсистемы без XML-файлов, и Конфигуратор падает на "Файл объекта не существует" / контейнер формата нужен, но его состав должен совпадать с реально оставленными дочерними подсистемами, включая исключенные ветки из `excluded_subsystems`
- 2026-04-22 / `style:Имя` внутри `Native`-форм участвует в `RefDrivenInclusion` как ссылка на `StyleItem.Имя`, если соответствующий `StyleItem` реально есть в исходной XML-выгрузке / иначе нативная форма может сохранить ссылку на кастомный цвет стиля, а сам `StyleItem` потеряется и загрузка формы упадет на XDTO-ошибке цвета / встроенные style-константы в метаданные не превращаем
- 2026-04-23 / В `dynamic list contract` declared-поля из `Settings/Field` считаются обязательным retained-составом, а не виртуальными alias / иначе `AdoptedStubExt(Form)` ложно проходит валидацию и теряет реальные поля вроде `Комментарий` и nested-path `Состав.Пользователь` / nested path нужно сохранять целиком, а стандартные поля строки табличной части (`Ссылка`, `НомерСтроки`) считать встроенными платформенными
- 2026-04-24 / Если manual-query `DynamicList` после cleanup формы остается без `MainTable`, прямые select-поля нужно явно alias-ить как `КАК Поле`, а form-layer не должен хранить стандартные row-команды `Change` / `ChangeHistory` / `GetURL` / `LevelDown` / `LevelUp` и `RowPictureDataPath=<Атрибут>.DefaultPicture` / иначе после корректного adopted-cleanup target-объекта Конфигуратор начинает падать уже на самой форме: на `Неверное имя команды элемента формы` и `Неверный путь к данным`
- 2026-04-24 / Для `AdoptedStubExt(Form)` у `Catalog` нужно минимализировать `Properties` до stub-уровня, а не оставлять почти полный исходный каталог / один только retained child-состав и исправленный `ConfigDumpInfo.xml` не устранили ошибку `Неверный путь к данным` в форме `упо_ОграничениеДоступаПоОбъектамPM`; в дампе оставались лишние свойства каталога вроде `InputByString` и других полных настроек / нормализация form-driven adopted-stub должна приводить `Catalog`, `Attribute` и `TabularSection` к минимальному набору свойств, близкому к выгрузке Конфигуратора
- 2026-04-27 / Мягко исключенный объект не возвращаем в `AdoptedStub`, если все допустимые входящие ref-driven ссылки на него идут только из `Native`-подсистем / такой кейс всплыл на `CommonModule.БюджетированиеСервер` и `CommonModule.ЗакрытиеМесяцаСервер`, которые повторно входили через excluded-ветку `упо_ИнтеграцияERP` и другие нативные подсистемы / для возврата мягко исключенного объекта теперь нужен хотя бы один другой допустимый источник ссылки, не сводящийся к одной лишь подсистемной группировке
- 2026-04-27 / `AdditionalProcessing.Use_MetaDataFile` вводит частный режим `AdoptedStubMetaData` / часть объектов нужно включать в adopted-режим по общему макету `упо_MetaDataFile`, но child metadata при этом сохраняется только для реквизитов с префиксом `упо_` из множеств `Реквизиты` и `ТабличныеЧасти` / это отдельный слой над обычным `AdoptedStub`
- 2026-04-27 / `excluded_subsystems` должны исключать связанные top-level объекты раньше primary `Native` по native-prefix / кейс с `DataProcessor.упо_ФормированиеЗаказовЭлементаПлана` показал, что одного префикса `упо_` достаточно, чтобы объект оставался `Native`, хотя он должен уходить вместе с исключенной подсистемной веткой / правило сужено именно к `excluded_subsystems`, без общего переворота семантики `excluded_objects`
- 2026-04-27 / `Native`-подсистемы не считаются источником `RefDrivenInclusion` для восстановления excluded-объектов / кейс с `Enum.ХозяйственныеОперации` показал, что одних подсистемных `MDObjectRef` достаточно, чтобы soft-excluded объект возвращался в состав, хотя пользовательская семантика считает подсистему только группировкой / восстановление excluded-объекта теперь допускается только от реальных `Native`-объектов и их форм
- 2026-04-27 / `Form.xml` должен чистить элементы формы с висячими metadata-command ссылками / кейс `Catalog.ВнешниеПользователи.Command.ВнешнийДоступ` показал, что adopted-каталог уже потерял child-команду, но формы `Catalog.Контрагенты` продолжали держать ссылку в `<Command>` / исправление должно удалять элемент формы, а не возвращать команду в adopted-состав без отдельного правила
- 2026-04-28 / `excluded_objects` для top-level metadata тоже должны срабатывать раньше primary `Native` по native-prefix / кейс с `DataProcessor.упо_СопоставлениеФинансовыхСтатейСтатьямБюджетов` показал, что явное soft-исключение по конфигу терялось из-за одного префикса `упо_`, а обратных ссылок кроме `Native`-подсистем не было / после такого soft-исключения subsystem-only ref-driven ссылки не должны возвращать объект в состав
- 2026-04-28 / `Role/Ext/Rights.xml` не должен восстанавливать excluded-объекты по `RefDrivenInclusion` / кейс с `DataProcessor.упо_СопоставлениеФинансовыхСтатейСтатьямБюджетов` показал, что soft-excluded объект удерживался ролью `упо_ПросмотрСопоставлениеФинансовыхСтатейСтатьямБюджетов`, хотя права являются служебным слоем, а не основанием для возврата объекта / права на excluded metadata-path теперь очищаются из роли, а role-rights не участвуют в таком восстановлении
- 2026-04-28 / список soft-excluded объектов должен собираться единым набором: объекты из `excluded_subsystems`, дополненные единичными объектами из `excluded_objects` / отдельная проверка `belongsToExcludedSubsystem` внутри `decideObject` дублировала и раздвигала логику классификации / после сборки общего `excluded`-набора дальнейшая обработка должна быть одинаковой для всех soft-excluded объектов
- 2026-04-28 / Если retained child metadata (`Attribute` / `Dimension` / `Resource` / `Measure`) у top-level объекта хранит `Properties/Type` на excluded-объект, нужно удалять весь child-узел / кейс с `Document.ОтражениеЗарплатыВФинансовомУчете` оставлял `cfg:CatalogRef.упо_НачисленияPM` и `cfg:CatalogRef.упо_НачисленияЗУП`, хотя сами каталоги уже были исключены / cleanup excluded-ссылок должен убирать не только отдельные reference-value элементы, но и child metadata, которые иначе становятся структурно невалидными по типу
- 2026-04-28 / `AdoptedStubMetaData` из `CommonTemplate.упо_MetaDataFile` не должен возвращать top-level объект, если он уже попал в единый `excluded`-набор / кейс с `Document.ОтражениеЗарплатыВФинансовомУчете` показал, что документ был soft-excluded ветками `РаспределениеЗаработнойПлаты` и `ИнтеграцияERP`, но снова входил в состав только из-за `Use_MetaDataFile=true` / приоритет soft-exclude должен оставаться выше metadata-file include
- 2026-04-28 / metadata-ссылки в type-bearing XML должны распознаваться и чиститься независимо от namespace alias / `Ext/Predefined.xml` использует current-config префиксы вроде `d4p1:CatalogRef.X`, а `Properties/Type` хранит ссылки как отдельные `v8:Type`; если этот слой не участвует в ref-graph и cleanup, в дампе остаются висячие типы и предопределенные элементы, которые потом валят загрузку нативных `ChartOfCharacteristicTypes` и других объектов
