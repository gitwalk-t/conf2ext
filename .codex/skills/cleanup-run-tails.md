# Skill: cleanup хвостов прогона

## Когда использовать

Используй этот helper:
- перед запуском нового прогона
- если пользователь просит снять хвосты
- если завис wrapper `powershell`
- если status helper показывает `PAUSED_AFTER_SUCCESS`
- если остались старые `go` / `1cv8.exe`

## Назначение

Skill отвечает только за безопасный cleanup project-процессов.

Skill не запускает новый прогон.
Skill не делает monitoring.
Skill не анализирует ошибки XML.

## Какие процессы можно трогать

Разрешено завершать только процессы, относящиеся к текущему проекту.

Текущий проект = текущий worktree / текущий `cwd`, из которого будет запускаться или уже запускался прогон. Если рядом есть другие worktree того же репозитория, не смешивай их pid-файлы, логи и процессы.

Проверять по совокупности признаков:
- `CommandLine`
- `--config`
- stdout/stderr log path
- pid-файлы
- timestamp запуска
- parent-child связь wrapper powershell -> go -> 1cv8.exe
- более поздний `StartTime`

## Запрещено

Запрещено:
- завершать чужие `1cv8.exe`
- завершать неподтвержденные фоновые процессы
- завершать процессы только по имени
- завершать процессы без проверки принадлежности проекту

## PowerShell gotchas

Чтобы cleanup не падал из-за особенностей PowerShell:
- не используй `$PID` как имя переменной: это встроенная read-only переменная (PID текущего PowerShell-процесса)
- для чтения PID из файла используй нейминг вроде `$pidVal`, `$wrapperPid`, `$runPid`

## Стандартный cleanup перед новым прогоном

Перед новым запуском:

1. Найти старые wrapper `powershell`
2. Найти связанные `go`
3. Найти связанные `1cv8.exe`
4. Завершить только подтвержденные project-процессы
5. Не трогать остальные процессы

Дополнительно:
- не считай `output/_log/last_run.txt` единственным источником истины: он может остаться от старого запуска
- первичный источник для cleanup — `run-*.pid`, stdout/stderr конкретного worktree и подтвержденная process-chain
- если pid-файл старый, но process-chain уже не существует, ничего дополнительно завершать не нужно

## Cleanup зависшего wrapper после успешного ChangeFiles

Если wrapper `powershell` / дочерний `go run` ещё жив, но фактически висит только на:

```text
Press any key to exit...
```

то его можно завершить.

Завершать можно только если одновременно выполнены все условия:

- stdout содержит `Press any key to exit...`
- `ChangeFiles` завершился успешно
- прогресс дошёл до конца:
  `apply object changes N/N file=done`
- dump snapshot уже сохранён в:
  `output/_log/xml_dumps/v8_src*`
- dump подтвержден как dump расширения
- wrapper/process относится к текущему запуску
